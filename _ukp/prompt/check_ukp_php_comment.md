## 주석 작성 규칙
### 기본 구조
- PHPDoc은 /**로 시작하고 */로 끝난다.
- 각 내부 줄은 ` *`로 시작한다.
- 첫 부분에는 함수의 기능을 - 로 시작하는 설명으로 작성한다.
- 기능 설명과 메타 정보, 메타 정보와 파라미터/반환값 설명 사이에는 빈 주석 줄( *)을 둔다.
- `require`, `@version`, `@param`, `@return`의 순서로 작성한다. 단, 파라미터나 반환값이 없는 함수에는 해당 태그를 강제하지 않는다.
### require 및 @version
- `require`는 프로젝트 자체 규칙이며 표준 PHPDoc 태그로 취급하지 않는다.
- `require  YYYY.MM.DD {의존 함수명...}` 형태를 사용한다. 의존 함수명이 없으면 날짜까지만 작성한다.
- `@version YYYY.MM.DD` 형태를 사용한다.
- 날짜 표기는 `YYYY.MM.DD`로 통일한다.
- 실제 의존 함수의 존재 여부나 날짜의 최신 여부는 검사하지 않는다.
### @param
- `@param {자료형} ${변수명}`을 한 줄로 작성한다.
- 파라미터 설명을 다음 줄에 반드시 작성한다.
- 배열 요소를 설명해야하면 파라미터 설명 이후 줄에 `` - `[키]` `` 설명 형태로 작성한다.
- @param의 변수명이 실제 함수 선언의 파라미터와 일치하는지 검사한다.
- 배열 자료형은 요소 자료형까지 표기한다. 예: `array<string,array<int,string>>`.
### @return
- `@return {자료형}`을 한 줄로 작성한다.
- 반환값 설명을 다음 줄에 반드시 작성한다.
- 배열 요소를 설명해야하면 반환값 설명 이후 줄에 `` - `[키]` `` 설명 형태로 작성한다.
- 배열 자료형은 요소 자료형까지 표기한다. 예: `array<string,array<int,string>>`.
### 배열 요소 설명 표기법
- `[키]`는 고정된 배열 키를 의미한다.
- `[{이름}]`은 동적으로 정해지는 배열 키를 의미한다.
- `[]`는 숫자 인덱스로 이어지는 배열 요소를 의미한다.
- 중첩 배열 경로는 연결해서 표기한다. 예: `[{데이터베이스명}][]`.
- 배열 경로 설명과 선언된 PHPDoc 자료형이 논리적으로 일치하는지 확인한다.
- 배열 경로 표기법은 프로젝트 자체 문서 규칙이며 PHPDoc의 공식 표준 문법이라고 주장하지 않는다.
## 올바른 주석 작성 예시
```php
/**
 * - 프롬프트 작성시 업로드할 md파일 생성
 * - ddl 기준으로 전체 데이터베이스 생성
 * - src 는 빈문자열인경우 prompt/upload_db.md 파일에 저장됨
 *
 * require  2026.10.15
 * @version 2026.10.15
 *
 * @param array<string,array<int,string>> $db_arr
 * db 및 테이블 배열
 * - `[{데이터베이스명}][]` 테이블명
 * @param string $src
 * 파일명이 포함된 저장경로
 * @return array{bool:bool,msg:string}
 * 생성결과
 * - `[bool]` 생성성공여부
 * - `[msg]`  결과상세내용
 */
```
